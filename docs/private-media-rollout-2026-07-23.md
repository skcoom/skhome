# 社内写真の非公開化　展開手順

## スタッフから見える変化

- 管理画面から追加した写真と動画は、最初は必ず「社内のみ」になる。
- 写真の「掲載する」を明示的に押したときだけ、公開サイト用のコピーが作られる。
- 「掲載をやめる」に戻すと、公開サイト用のコピーが削除される。社内用の原本は残る。
- LINE写真・AI判定画面の件数は、選択中の現場だけを正しく集計する。

## 確認済みの実データ

2026年7月23日の読み取り専用調査で、次を確認した。

- 現場: 8件（すべて非公開）

  - 管理画面から登録: 154件
  - LINEから受信: 2件

- LINE写真: 2件（非公開R2保管、非掲載）
- PDF書類: 2件（見積書、旧公開保管先）

写真と書類は実データと判断し、一括削除せず非公開保管先へ移す。重複ユーザーも、別途承認を得るまで削除しない。

## 保管設計

| 対象 | 原本の保管先 | 管理画面での閲覧 | 公開方法 |
| --- | --- | --- | --- |
| 管理画面から追加した写真・動画 | Supabaseの非公開領域 `project-media-private` | 15分間のみ有効な署名付きURL | 人が掲載を承認したものだけ `project-media` へコピー |
| LINE写真 | 非公開R2 | 既存の社内用署名URL | 既存のLINE専用承認操作でコピー |
| PDF書類 | Supabaseの非公開領域 `project-documents` | 15分間のみ有効な署名付きURL | 公開しない |

LINE原本のR2保管はそのまま維持する。今回追加するのは、管理画面から登録する通常写真の非公開保管である。

## 検収の順序

1. `supabase/migrations/20260723000000_private_project_media.sql` を適用する。カラムと非公開保管先の追加だけで、この時点で既存データは移動しない。
2. プレビュで管理画面にログインし、写真の追加、「社内のみ」表示、掲載、非掲載化を1件で確認する。
3. 承認後に本番コードを反映する。
4. 本番画面の基本確認後、既存写真と書類の移行をまずドライランする。
5. 件数を確認し、別途承認後に `--apply` を付けて移行する。
6. 管理画面で既存写真とPDFを開けること、公開サイトに非掲載写真が出ないことを再確認する。

## 再現・移行コマンド

```bash
npm ci
npx tsc --noEmit
npm test -- --runInBand
npm run lint
npm run build

# ここから下は、対象環境の接続情報を設定した管理者端末で実行する。
# 初回は読み取りだけで、件数を確認する。
npm run migrate:private-media
npm run migrate:private-documents
npm run cleanup:test-users -- --email=skcoom.8814@gmail.com

# 次の3行はデータを変更する。個別の明示承認後にのみ実行する。
npm run migrate:private-media -- --apply
npm run migrate:private-documents -- --apply
npm run cleanup:test-users -- --email=skcoom.8814@gmail.com --apply --confirm=skcoom.8814@gmail.com
```

`SUPABASE_SERVICE_ROLE_KEY` は表示・共有・リポジトリへの保存をしない。本番移行はプレビュ検収と明示承認の後に行う。
