# 技術スタック更新チェック

SKhomeで使用している技術の最新情報をチェックし、プロジェクトへの影響を判定する。

---

## 目的

外部の技術情報を定期的に確認し、プロジェクトの技術的な陳腐化を防ぐ。

---

## 実行手順

### ステップ1: ソース一覧の読み込み

`_config/sources/tech-sources.md` を読み込み、チェック対象と各ソースの `last_checked` を把握する。

優先度:
1. **高**: Next.js、React、Supabase
2. **中**: Tailwind CSS、Anthropic、TypeScript
3. **低**: ESLint、Vercel

---

### ステップ2: 更新有無の軽量チェック

各ソースの最新記事・リリースの日付のみを確認する。

**チェック方法**:
- ブログ: トップページの最新記事の公開日
- GitHub Releases: 最新リリースの日付

**判定**:
- 最新記事の日付 > last_checked → 更新あり（詳細確認へ）
- 最新記事の日付 <= last_checked → 更新なし（スキップ）
- last_checked が `-` の場合 → 初回なので更新ありとして扱う

このステップでは記事の内容は読まない。日付の確認のみ行い、トークン消費を抑える。

---

### ステップ3: 更新ありソースの詳細確認

ステップ2で「更新あり」と判定されたソースのみ、内容を確認する。

**確認する内容**:
- 新バージョンのリリース
- APIの仕様変更
- 非推奨化・廃止のお知らせ
- 新機能・改善
- セキュリティ関連の発表

---

### ステップ4: ウォッチリストの確認

`_config/sources/tech-sources.md` の「ウォッチリスト」セクションを確認する。

**確認内容**:
- 各ウォッチ項目の状況に変化があるか
- 関連技術の公式発表で対応が発表されたか
- GitHub Issues/PRで進捗があるか

**状況の更新**:
- `待機中` → 公式発表があれば `対応可能` に変更
- `対応可能` → 対応完了したら項目を削除し、更新履歴に記録

---

### ステップ5: SKhomeへの影響判定

収集した情報と、以下のSKhome設定を照らし合わせる:
- `CLAUDE.md`（プロジェクト規約）
- `package.json`（依存バージョン）
- `src/` 配下のコード

**判定基準**:
- 現在使用中の機能に影響があるか
- アップデートが必要か
- コード修正が必要か

---

---

### ステップ7: last_checkedの更新

レポート完了後、`_config/sources/tech-sources.md` の各ソースの `last_checked` を今日の日付に更新する。

---

## 使用するリソース

| リソース | 用途 |
|---------|------|
| `_config/sources/tech-sources.md` | チェック対象ソース一覧、last_checked管理 |
| `CLAUDE.md` | 現在のプロジェクト規約との照合 |
| `package.json` | 依存バージョンの確認 |
| WebFetch | 各ソースの更新日付・内容取得 |

---

## 完了条件

- [ ] 優先度「高」のソースの更新有無がチェックされた
- [ ] 更新ありソースの内容が確認された
- [ ] ウォッチリストの各項目が確認された
- [ ] SKhomeへの影響が判定された
- [ ] 結果が指定フォーマットで報告された
- [ ] `last_checked` が更新された

---

## 推奨実行頻度

- 週1回程度
- 重要な発表があった時（新バージョンリリース等）
